Settings > Appearance: themes, accent, editor scheme

Specs

Support the theme settings of the reference screens: a Theme dropdown (Islands Light/Dark, High Contrast, Solarized Light/Dark, One Light/Dark), Sync with OS, Editor color scheme, Accent colour (presets and hex) and Different tool window background. Scope chosen: those settings only (not Accessibility or UI Options), applied across the whole app.

Actions

  • GobiModel/AppTheme.swift: AppTheme (7 themes, palettes), ThemePalette, AccentChoice, ThemeSettings (stored text), hex helpers on RGB. 9 tests in AppThemeTests, written first; they also check text contrast of every theme.
  • GobiEditor/ThemeColors.swift: the current theme as NSColors; SyntaxTheme, the highlighter's base text colour, the gutter and EditorView.applyTheme() use it and repaint when the revision changes.
  • GobiApp/ThemeController.swift: sets the app brightness, styles every window, follows macOS appearance changes. AppPreferences.theme stores the settings.
  • GobiApp/AppearanceSettingsPane.swift: the new Appearance tab (last tab, so existing tab indices are unchanged). The old System/Light/Dark switch and its key were removed.
  • All controlAccentColor uses became ThemeColors.accent; terminals take background, text and caret from the theme.

Tradeoffs

  • Most backgrounds in the app are clear and show the window, so the theme works by colouring the window and the editor, not by replacing every semantic colour. Controls drawn by AppKit (buttons, popups) keep the system look in light or dark.
  • Text colours still come from the system's light or dark appearance, matched to the theme's brightness; they are not individually themed.
  • Different tool window background colours the window itself (the area around the editor), since tool windows are transparent.
  • The system accent for AppKit controls cannot be overridden; the accent applies to Gobi's own highlights, selection and caret.
  • Default changed to One Dark and One Light following the OS, so everyone's colours change on update.
  • The UI part has no automated test (the app target has none) and was only built, not run.
