Binary handshake and control channel

Specs

The UI and gobid talked JSON everywhere. Move the messages gobid owns to a binary format with a fixed layout.

Actions

  • core/internal/wire and GobiClient/Wire.swift: protobuf wire format, hand-coded, same golden bytes in both test suites, Go fuzz test.
  • Handshake (ipc) and control channel (daemon/control.go, ControlClient) are binary; a JSON handshake gets a readable refusal.
  • docs/architect/wire-protocol.md lists every field number.
  • End to end: gobi-check project, the file and project self-tests (LSP through the new handshake) and gobi-probe against a rebuilt gobid.

Tradeoffs

  • The LSP channel stays JSON-RPC: gopls speaks it, and the broker's byte splice is faster than decoding and re-encoding every message.
  • No JSON fallback for the handshake: one format is easier to keep stable; old clients get a clear error.
  • Hand-coded instead of generated protobuf: no dependency or tooling in a Command Line Tools-only build; the bytes stay protobuf-compatible so a schema can replace it.
