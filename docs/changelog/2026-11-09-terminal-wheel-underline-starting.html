Terminal: wheel scrolling, stray underline, "Starting shell…"

Specs

  • The wheel did nothing inside Claude Code in the Gobi terminal.
  • Every line was underlined once Claude Code started.
  • Opening a terminal showed nothing for a second or more while the shell started.

Actions

  • GobiTerminalView.forwardWheel and a local scroll-wheel monitor in TerminalPane: the wheel goes to the program as wheel mouse events when it asked for the mouse, else as arrow keys on the alternate screen; Shift keeps local scrollback.
  • TerminalOutputFilter (GobiModel) drops ESC [ > Pm m, which SwiftTerm read as SGR underline; held across chunk boundaries. 4 tests in TerminalOutputFilterTests, red then green.
  • A dim "Starting shell…" line, cleared on the first output, an exit or an error.

Tradeoffs

  • SwiftTerm's scrollWheel is not open and the version is pinned, so a monitor and an output filter were used instead of patching or forking it.
  • The wheel position sent to the program is the pointer's share of the view, not an exact cell.
  • The wheel and starting-line changes have no automated test (the app target has none); the filter is unit tested and was checked against a real captured Claude Code stream.
  • "Starting shell…" hides the delay rather than shortening it; most of it is the user's shell startup files.
