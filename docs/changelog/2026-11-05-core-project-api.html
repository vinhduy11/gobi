Core project API

Specs

New Project, Open, Clone and Import need support in gobid before the UI can offer them (roadmap: project lifecycle).

Actions

  • internal/project: name and module validation, templates, Create, Inspect, Import, Clone, ModulePathFromRemote.
  • daemon/control.go: JSON-RPC style requests on the control channel: project/new|open|clone|import.
  • Tests written first: unit tests, a build of a generated project, git init on master, clone from a local repository, and an end-to-end test through the socket.

Tradeoffs

  • Requests on one connection run in order; a long clone blocks later requests on that connection.
  • Clone validates the URL and also restricts git's transports, so a crafted URL cannot run commands.
  • No gRPC template (it needs dependencies and generated code) and no "add to an existing go.work" yet.
  • The environment profile option in the New Project mockup waits for the environment-profile work.
