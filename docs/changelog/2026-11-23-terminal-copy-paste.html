Terminal copy returned an empty string

Specs

Bug report: in the bottom-panel Terminal, copy and paste do not work. Acceptance: selecting text and choosing Copy (⌘C or Edit > Copy) puts that text on the pasteboard; Paste sends the pasteboard text to the shell.

Actions

  • Root cause: Vendor/SwiftTerm/Sources/SwiftTerm/SelectionService.swift, getSelectedText(). For a forward selection max was set to start, so min equalled max and Terminal.getText returned "". The terminal's copy(_:) therefore cleared the pasteboard and wrote "" (Copy on select was affected the same way). Fixed: max is end unless the selection runs backward.
  • Tests (Tests/TerminalForkTests/ClipboardTests.swift): copy puts the selection on the pasteboard (was red), paste sends the pasteboard text, and Copy/Paste validate as enabled on the terminal.
  • Recorded the patch in Vendor/SwiftTerm/VENDORED.md and CHANGELOG.

Tradeoffs

  • Patched the vendored library (as the other fixes are) instead of re-implementing the selection text in GobiTerminalView: one line, and covers every caller.
  • Paste worked in the headless check when the terminal is the target, so no paste change was made. Not verified: a paste failure inside the running app (real key event, menu validation with the real key window, a connected shell). Pasted text is sent raw (no bracketed paste), as in SwiftTerm 1.5.1.
  • The responder chain and menu key equivalents could not be driven headless (no key window), so the tests send the actions to the terminal directly.
