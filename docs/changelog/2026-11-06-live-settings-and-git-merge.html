Live settings and git merge

Specs

Build the Settings controls that were drawn disabled and have a real local feature behind them (terminal scrollback, start folder, copy on select, quit confirmation, git path, auto-fetch, gopls path, large-file limit), and add Merge into Current Branch to the git channel and the branch menu.

Actions

  • Core: gitsvc.Merge (no editor, abort on conflict), gitsvc.Fetch, gitsvc.SetExecutable; git channel kinds 13 and 14; handshake field 9 tool (git path, gopls path) with an admit check; the lsp registry keys a server by its tool path.
  • GobiModel: terminal scrollback, start folder, copy on select; confirm quit; git path and fetch interval; advanced settings (gopls path, line limit); wire encodings; tests in LiveSettingsTests, GitStatusTests, WireTests.
  • App: settings panes, copy-on-select terminal view, new-terminal scrollback and start folder, quit confirmation, fetch timer, merge menu item and confirmation, editor line limit; self-test checks for each.

Tradeoffs

  • The git path is process-wide in gobid (last git session wins) rather than per session: one person owns the daemon and one setting.
  • SwiftTerm fixes scrollback when a view is made, so the setting applies to new terminals only; resetting an open buffer would drop its content.
  • Copy on select hooks the open selectionChanged callback; no public selection API exists to drive a real drag in the self-test.
  • Merge uses a pick-a-branch confirmation sheet and aborts on conflict instead of leaving a half-merged tree; conflict resolution in the editor is not built.
