JSON and Markdown language service

Implementation report, 2026-11-05

Specs

Support .json and .md files out of the box. Agreed scope: the core provides the language features and the UI does syntax colouring.

  • JSON: syntax errors with line and column, formatting, outline.
  • Markdown: outline by heading, HTML preview.
  • Runs through the same broker as gopls (restart, id translation, shared between windows). No external tool to install.
  • Mockups for the new screens plus Settings and the menu bar.

Actions

AreaWhat was done
internal/langsvcLSP server over stdio: strict JSON parser with outline and error offsets, JSON formatter, Markdown heading extraction with fence handling, goldmark preview, document sync, diagnostics. 50+ test cases; fuzz test keeps the JSON parser equal to encoding/json (4.2M executions, no difference).
Wiringgobid langserver subcommand; handshake language field with an admit hook; registry keyed by root, language and trust level; daemon takes a language-to-command map and refuses unknown languages. End-to-end tests drive JSON diagnostics, formatting and the Markdown preview through the real socket and the built binary.
DocsArchitecture section, dependency and licence review (x/sys BSD 3-Clause, goldmark MIT), README, CHANGELOG.
MockupsJSON editing, Markdown split preview, menu bar (all menus), Settings Editor and Languages; offline copy in docs/artifact/.

Tradeoffs

DecisionChosen overWhy, and the cost
Built-in service in Govscode-json-languageserver and marksmanNo Node or extra binaries to install, one process model. Cost: fewer features (no schema validation, no link checking).
Runs as a subprocess of gobidIn-process goroutineReuses the broker unchanged and isolates crashes. Cost: one more process per workspace and language.
Hand-written JSON parserencoding/json errorsGives exact offsets and the outline in one pass. Cost: must stay identical to the standard library, which the fuzz test enforces.
Strict JSONJSON with commentsMatches .json semantics. Comments and trailing commas are reported as errors.
Full-text document syncIncremental syncSimplest correct option; every change re-sends the file. Switch if very large files feel slow.
Raw HTML dropped from the previewAllowing HTMLThe preview can be shown without scripts. Cost: README files that rely on inline HTML render without it.
No outline while a JSON file has an errorPartial outlineKeeps the parser small. The outline reappears when the error is fixed.

Known gaps

  • Syntax colouring, the preview pane and the format command are UI work in the Swift slices.
  • No JSON Schema validation and no JSON with comments.
  • Setext headings take only the line above the underline.
