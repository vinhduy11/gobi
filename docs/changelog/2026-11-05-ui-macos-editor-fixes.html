macOS editor fixes

Implementation report, 2026-11-05

Specs

Fix what the editor spike and an independent check found, on a 100k-line Go file: a scroll slowdown, diagnostics wiping syntax colours, unusable accessibility queries, measurement errors, and very long lines. A smaller model did the list in docs/implement/ui-macos-fixes.md; its results were rerun before this report.

Actions

ItemResult (rerun and confirmed unless noted)
Far scroll jumpEditorClipView maps big jumps to text positions. One far jump: stock 737 ms and 165 ms per keystroke afterwards; fixed 4 ms and 3.1 ms, memory 175 MB vs 118 MB.
Scroller dragA drag now applies one jump when it ends. Keystrokes after a drag 10.4 ms to 2.2 ms, memory growth +139 MB to +26 MB. Trade-off: the text does not follow the thumb while it is dragged.
Diagnostics vs coloursUnderlines add and remove only their own attributes; a diagnostic on a keyword keeps its colour (self-test check added).
AccessibilityEditorTextView answers caret line, line for index and range for line from the line index: 7.9 s and 210 ms became 0.0 ms. A real VoiceOver pass is still needed.
MeasurementPaint is measured with CATransaction.flush(); displayIfNeeded() paints nothing. Keystroke plus paint about 5.4 ms.
Self-testA missing file exits with code 1 in under a second instead of hanging.
Long linesLines over 20,000 characters are not coloured and the status bar says so. 1 MB single-line JSON: 13.7 s to 151 ms per keystroke.
LSP clientA timed-out request no longer leaves its pending entry (2 tests). 43 Swift tests pass.

Tradeoffs

DecisionChosen overWhy, and the cost
Remap large jumps to text positionsFixed line height, invalidateLayoutThe alternatives were measured and were worse. Cost: the view lands on a line, not an exact pixel.
Apply a drag when it endsLive scrolling with throttlingCut post-drag keystrokes from 10 ms to 2 ms. Cost: no live feedback while dragging; throttled live jumps remain an option.
Skip colouring on very long linesColouring everythingColouring was what cost 13 s per key. Cost: long minified lines have no colours.
LineIndex keeps \n as the line breakAlso U+2028 and lone CRMatches the LSP for \n and \r\n. A lone CR is a known gap for diagnostic positions.

Known gaps

  • Stale syntax colours: after typing /* then */, or typing in front of var, colours can stay wrong. Reproduced, root cause not found, no fix.
  • 1 MB single line is 151 ms per keystroke, not under the 100 ms target: TextKit lays out one huge paragraph per edit.
  • Find in file and trackpad momentum could not be driven from code (inconclusive).
  • The line-separator checks in the harness still fail, including the control case, so that hypothesis is ruled out but the failure is unexplained.
  • VoiceOver and a real input method have not been tried.
