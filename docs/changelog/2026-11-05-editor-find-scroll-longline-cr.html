Editor: find, scrolling, long lines, lone CR

Specs

Close five open items: find in file, trackpad momentum scrolling, 151 ms per key on very long lines (target 100 ms), a lone \r not counted as a line break, and the scroller thumb only moving the text on release. Later request: GUI checks must not pop up windows.

Actions

  • LineIndex (Swift) and internal/textlines (Go): \n, \r\n, \r; replace returns a LineChange; randomized tests against a rebuild.
  • EditorClipView: throttled live jumps while dragging; gobi-check scrollthrough for continuous scrolling.
  • EditorDocument.editableLineLimit (550,000): read-only with a status notice; fixtures and gobi-check longline.
  • FindBar, Edit > Find menu items, EditorView find API, reworked gobi-check find.
  • Quiet mode: accessory activation policy, invisible window, no activation; --visible opts in.
  • Mockup board "Find in file and read-only notice".

Tradeoffs

  • Own find bar instead of NSTextFinder: the standard one could not be verified from code; ours is simpler to test, but has no regex, case option or match count yet.
  • Read-only above 550,000 characters instead of a custom view: a custom text engine for huge lines is far more work for a rare case.
  • Live drag is throttled, so the thumb can settle a few percent off the release point.
  • Real trackpad momentum is checked by hand; it cannot be synthesized.
