Generate in the macOS app (stages 4b, 4c-UI, 4d)

Specs

Generate… (⌃N, editor and Explorer menus, Edit menu) shows what applies at the caret, runs the Design Pattern dialog with a live preview, inserts the result as one undoable edit, creates files for tests and new-file patterns, offers gopls' Fill struct, and offers five folder items in the Explorer. The mocks are the Generate and Context menus boards.

Actions

  • GobiModel: Generate.swift (wire types), GenerateContext.swift (request from the symbol model, signature parser, caret placement), GeneratePopup.swift (entries by group, dialog form and hints, icons); menu spec, icons, CodeAction.resolveData, GoModule.goDirective.
  • GobiClient: ControlClient.generateList/Preview/Render, codeAction/resolve, code action capabilities with dataSupport.
  • GobiApp: GenerateUI.swift, GenerateSheet.swift, GenerateSelfTest.swift, --selftest-generate.
  • Core: folder items (folder.go), Implement Interface (implement.go), request golden bytes shared with Swift.

Tradeoffs

  • Resolve support makes gopls send every lazy action without its edit; the client resolves on use instead of keeping the old capabilities, because the owner chose codeAction/resolve for Fill struct.
  • Implement Interface works from the same buffer only: gopls offers it as a quick fix for a type error, and the owner chose our own snippet.
  • The popup lists what applies (the mock draws everything); titles come from core.
