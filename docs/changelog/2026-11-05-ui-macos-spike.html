macOS editor spike

Slice 2 implementation report, 2026-11-05

Specs

Prove the vertical path (open a file, start gobid and the language server, show diagnostics in an AppKit window), measure a 100k-line file and Vietnamese input, assemble a signed .app, and decide whether stock TextKit 2 can carry the editor. Run on the Command Line Tools only. Also requested: load a large Go file and test open, run and load.

Actions

AreaWhat was done
GobiClientFrame decoder on [UInt8] (13 tests), incremental UTF-16 line index (9 tests including a 2000-edit randomized equivalence check), unix-socket connection, handshake, LSP client, gobid discovery with on-demand start.
GobiAppTextKit 2 editor window, problems list, status line, incremental sync to the server, diagnostics as rendering attributes, menu bar, open panel. Same code path for Go, JSON and Markdown.
Toolsgobi-probe (headless end-to-end), gobi-bench (measurements), --selftest inside the app, scripts/make-app.sh (bundle, Info.plist, bundled gobid, ad-hoc signature, verified), scripts/test.sh.
Large fileGenerated a 100,012-line, 1.9 MB Go program: go run takes 3.7 s and prints the correct result. Opened a copy with an error on its last line in the app: first diagnostics in 0.64 to 1.85 s, error underlined, 100 mid-file keystrokes at a 2.1 ms median.
Root cause foundFirst numbers (2.3 s to open, 352 ms per keystroke, +724 MB) came from a non-tracking text container, which makes TextKit 2 lay out the whole document. A wide fixed-width view whose container tracks it takes 15 ms to open and 1.7 ms per keystroke at 160 MB. Two experiments in between were invalid (shell argument splitting) and were redone before drawing conclusions.
Follow-up: colours, gutter, painting, mousePer-line lexers for Go, JSON, Markdown with an incremental index (41 tests, randomized equivalence with a full rebuild), lazy rendering-attribute colouring, a line-number gutter, mouse/scroll/paint/typing checks inside the real window. On a 100k-line file: open 180 ms, keystroke 3.2 ms (3.7 ms with painting), highlighting costs about 1.4 ms per key, every mouse selection correct at 1 ms. Snapshots inspected by eye.
Problems found and fixedAppKit passed the --snapshot path to openFile and an error alert hung the app; NSRulerView covered the first characters of each line, replaced by a sibling gutter view; fixtures without go.mod gave no diagnostics.
Open riskDragging the scroller by pixel position on a huge file can take 0.6 to 2.9 s once and then slows typing to 100 ms per key. Jumping by text position avoids it (12 ms jumps, 5 ms keys), so the scroller must be mapped to lines before shipping. A fixed line height did not help.

Known gaps

  • Not measured: GPU compositing and frame pacing, trackpad momentum, a real scroller drag, find, VoiceOver, very long lines.
  • The scroller must be mapped to line numbers before the editor can ship (see the follow-up above).
  • Real Vietnamese input method not tried; manual checklist is in the findings note.
  • A GUI app inherits a minimal PATH, so gopls will not find go when launched from Finder.
  • Marked text is sent to the server edit by edit (seven messages for one word).
  • Diagnostics are applied to the current text without a document-version check.
